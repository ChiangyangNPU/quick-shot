QuickShot v0.1.5 —— 更新链路稳定性与 Retina 清晰度修复（GitHub / Gitee 双端同步发布）

## 🐛 修复

- **macOS Retina 截图与贴图模糊**：截图合成、选区裁剪、贴图窗口与滚动截图全链路改为按物理像素处理，2x 屏下贴图不再被系统二次放大而发虚；标注马赛克块大小同步按像素比换算，块观感与普通屏一致；历史截图新增 DPR 记录（老库自动迁移，升级前的旧图显示尺寸保持不变）。Windows 本身是 1:1 物理像素，路径不变，行为不受影响
- **OCR 英文识别单词粘连**：识别模型在字典末尾追加的空格类别，此前被 CTC 解码当作越界索引丢弃，英文结果所有单词连成一片；现按模型类别数正确识别该类别并输出空格
- **设置页取消更新下载必闪退**：`abort()` 会同步触发 `finished()` 重入并清空 reply，调用处随后对空指针 `deleteLater` 直接段错误；取消下载、检查超时、下载超时三条路径统一改为先摘下引用再 abort
- **取消更新下载后关于页高度不回收**：窗口高度回不到空闲态（底部大段空白），「正在下载更新...」文字取消后仍残留；高度测量改为失效后按新鲜 `sizeHint` 两步调整并延迟一拍复核，状态文字改走 `setText("")` 触发完整重算
- **更新渠道回退形同虚设**：跨渠道回退时按该渠道自己的地址模板重建下载地址，不再复用上一渠道的附件 URL 反复打同一台主机；同时从「检查成功的渠道」起步，不在已知不可达的渠道上白等超时
- **跨渠道重试的版本信息残留**：上一渠道遗留的 assets 与新响应混合，导致误用其他源的附件地址；`VersionInfo::fileSize` 显式初始化为 0，避免未初始化值造成大小校验误判
- **更新大小校验基准**：非本平台资产的 `fileSize` 不可信时放弃校验，不再误判下载失败
- **`version.json` 版本号解析**：与 release API 一致用正则提取数字段，`"v1.0"` 这类带前缀的值不再被当作 0 而漏报升级
- **更新失败原因可区分**：检查/下载失败日志带 HTTP 状态码，403 额外标注匿名 API 限流提示（60 次/小时/IP）
- **官网更新渠道数据源**：官网尚未上线，暂复用 Gitee 数据源（相当于多一次重试），渠道切换提示文案如实改为「Gitee（备用）」；响应解析改为按 JSON 内容形状判断，渠道与解析解耦
- **宠物页「系统状态」说明文字**：与右侧复选框垂直对齐，并统一为全局主文字色（原先小号灰字视觉偏上、与页面其它说明文字颜色不一致）

## 🛠️ 技术特性

- **历史记录 DPR 元数据**：`history_items` 新增 `image_dpr` 列（`ALTER TABLE` 自动迁移），PNG 本身不携带 DPR 的问题由此解决，Alt+P 翻页贴图可按截图时的真实像素比还原显示尺寸
- **Windows 本地临时包名**：对齐发布资产命名（`QuickShot-Release-v{ver}-…`），便于发布核对

## 🧪 工程化

- 新增 `AboutTabHeightTest`：复刻关于页结构，模拟「检查 → 发现新版本 → 下载 → 取消」全流程，断言窗口高度收敛回空闲值、状态文字清空
- `UpdateManager` 新增 `sourceChannel` 回归测试（Official 归一为 Gitee、GitHub/Gitee 不被改道），共 12 项全绿
- `OcrRecPostprocess` 增加英文空格解码用例；`HistoryManager` 增加截图 DPR 落库断言
- 架构文档同步更新渠道回退语义与版本信息清理规则

## 📦 安装包

| 平台 | 文件 | 说明 |
|------|------|------|
| Windows x64 | `QuickShot-Release-v0.1.5-Windows-x64.zip` | 解压即用，已含全部依赖 |
| macOS arm64 | `QuickShot-Release-v0.1.5.dmg` | 引导式安装窗口，把 QuickShot 拖入「应用程序」 |

> macOS 未做 Apple 公证：首次打开请**右键 →「打开」**放行；录屏 / 系统录音需在「系统设置 → 隐私与安全性」中授权。
> **升级提示**：通过应用内"检查更新"升级的用户无需任何操作（更新流程自动完成新旧交接）。手动安装时若启动新版提示「QuickShot 已在运行」，请先退出旧版本（托盘图标右键 → 退出）再启动。
